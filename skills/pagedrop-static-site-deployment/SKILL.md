# PageDrop 静态网页部署

工具入口：[PageDrop](https://hup.new.tg/)。原帖把它描述为在浏览器内上传文件、调用 GitHub 接口并配置 Pages 的工具；本次未审查网页源码，不能把“无后端”“仅会话保存 Token”当作已经验证的安全结论。

## 原帖部署流程

1. 准备 GitHub Token。原帖按 `repo`、`workflow` 两个 scope 描述授权，不要求全选权限；没有说明细粒度 Token 的权限配置或兼容性，不能直接把 scope 名照搬成另一种 Token 的授权表。
2. 选择已有仓库，或在工具中创建新仓库。
3. 拖入单个文件、文件夹或 ZIP 包。
4. 工具按原帖说明会上传文件、生成 GitHub Actions 配置并开启 Pages。
5. 查看自动刷新的构建进度，取得最终网页链接后打开检查。原帖说一般几分钟，未给出构建耗时保证。

## 文件、手机和维护

| 项目 | 原帖说明 |
|---|---|
| 单次上传 | 最多 50 MB，未说明十进制/二进制口径 |
| 手机上传文件夹 | 浏览器通常受限，先打包 ZIP 再上传 |
| 已部署文件 | 支持仓库文件浏览、在线修改和保存 |
| 自定义域名 | 内置 DNS 设置教程，未列出具体记录值 |
| Token 存储 | 项目自述仅在浏览器会话内，关闭标签页清除；未独立核实 |
| 费用 | 原帖称工具功能免费；不代表 GitHub 或域名相关服务的全部条件 |

这是静态文件部署流程；原帖没有说明服务器端应用、数据库、构建框架、ZIP 内目录结构或上传失败的处理方式。不要据此推导它能直接托管任意后端程序。
