# bees：面向 Btrfs 的块级数据去重工具

bees（Best-Effort Extent-Same）是一个面向 Btrfs 的去重代理。原帖将它介绍为 Linux 上用于 Btrfs 文件系统的去重工具；官方 README 则将其描述为面向 Btrfs 的块级用户态去重代理。

## 它做什么

常见的文件级去重会比较整份文件。两份文件只要有局部内容不同，就可能无法按整文件方式合并重复部分。bees 在 extent（文件系统数据区段）层面查找可去重的数据，因此目标粒度不同于删除重复文件或整文件去重。

官方 README 将其能力概括为块导向的去重，并说明它可对整个 Btrfs 文件系统扫描。去重对上层应用透明：应用仍通过文件系统访问数据；这不等同于删除重复文件，也不是垃圾文件清理。

## 范围与限制

bees 面向 Linux 上的 Btrfs。官方 README 明确指出其去重范围是整个文件系统：没有 include/exclude 过滤器，也不接受文件列表。因此不能把它描述成只选择某个目录或一组文件处理的工具。

官方 README 还列出以下注意事项：

- 需要 root 权限，具体包括 `CAP_SYS_ADMIN` 以及常规的文件系统读取和修改权限。
- 如果有很多快照，首次运行可能增加元数据空间占用。
- README 描述了守护进程的增量扫描能力，可逐步处理新出现的数据；它仍然是针对整个文件系统的工具。

## SSD 与 HDD 的说法

酷安原帖作者表示自己只建议 SSD 用户使用，并把机械硬盘上的碎片化代价作为顾虑。这是作者的使用偏好，不代表官方认定 HDD 不受支持，也不能推出 SSD 没有碎片化或读写成本。原帖和 README 都不足以给出适用于所有硬件、工作负载和文件系统状态的性能结论。

## 阅读与决策

bees 适用于希望在 Btrfs 文件系统层面查找重复数据、并能接受整文件系统作用范围的用户。若需求是限定目录、排除路径或传入文件清单，官方 README 所列功能并不满足这些条件。考虑使用前，应先阅读官方说明，评估文件系统范围、权限和首次运行的元数据影响。

本稿不提供安装或配置命令；原帖没有给出这些命令，官方 README 将安装、配置和运行说明分别链接到项目文档。

## 原帖举例与补充边界

原帖把虚拟机镜像和大量重复数据作为考虑场景，不代表这些文件实际都有可回收区段。官方 README 另说明可处理 live data，无需计划停机，并支持 Btrfs 压缩数据与增量扫描；这些是额外回读的项目说明，不是原帖已经给出的安装步骤。

本库没有启动 bees、扫描磁盘、修改 Btrfs 或进行去重；没有测量节省空间、I/O 和内存占用。本文是机制与范围说明，不是已经验证可部署的配置。
