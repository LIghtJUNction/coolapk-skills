# 安卓旗舰端侧大模型测试：线程数、带宽与长上下文

## 测试模型与框架

作者使用 MNN 开源框架测试 Qwen3.5 4B、9B int4 量化模型。第一组采用默认 4 线程，每款设备运行数轮并取平均；作者观察到 4 线程时 CPU 通常不如 GPU。CPU 预填充方面，玄戒 O3 和天玑 9600 Pro 略有优势；解码表现中，作者认为玄戒凭借 LPDDR6 带宽较稳定。作者同时指出新处理器的调度和框架适配等干扰因素很多，不能从这组数据得出稳定规律。

第二组使用 llm_bench，统一锁定 8 线程。手机装散热背夹，脚本监控电池温度，低于 26.5℃才开始；每项连续测三轮并取中间值。这组结果只在组内比较，不能与前一组 App 成绩直接对照。

- 4B：8 线程 CPU 基本都超过 GPU；CPU 预填充上玄戒和天玑表现较好，作者记录天玑解码相对弱。
- 9B：结果更不稳定；作者记录玄戒总体领先，骁龙 8 Gen 6 至尊版 CPU 预填充超过天玑和超级至尊版，天玑解码仍较弱。
- 长上下文测试：使用散热器，从 256 扩展到 8192 token。玄戒预填充从首档到末档下降约 18%，但仍最快；天玑预填充变化较小。解码衰减方面，作者称天玑最小但初始速度较低，8EE6 衰减幅度相近且最终排第一，玄戒衰减最大并降至第三。

原帖称长上下文测试中改用一加 16 而非 iQOO 16，因为 iQOO 在 6K、8K 档出现解码异常，作者怀疑与调度机制或 ADB 有关，原因未定。

## 作者报告的调度现象与结论边界

作者举例称 iQOO 16 可能采用时间预算型调度：任务开始时以 2.88GHz 档位运行，约 50 秒后回落到 2.42GHz 持续档；预填充速度因此从最高 100 出头降到 60 出头。原帖没有提供测量单位、设备完整配置或频率日志，数值应保留为该帖观察，不能作为其他设备的调度保证。

作者的总体判断是，短文本和简单对话的体感差距有限；长文档体验受内存带宽、生态和适配影响。NPU 的实际可用性还取决于厂商接口、框架支持与模型适配。作者称骁龙和天玑有 SDK 或工具可用、玄戒当时较封闭；这是发帖时的观察，不代表后续版本状态。
