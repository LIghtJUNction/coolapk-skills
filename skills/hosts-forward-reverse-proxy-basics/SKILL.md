# 区分 hosts、反向代理与正向代理

## hosts：静态名称到地址映射

hosts 是操作系统名称解析机制使用的静态映射表，可将主机名映射到 IP 地址。例如：

```text
192.168.1.100 example.com
```

应用或系统是否先查 hosts、hosts 相对于 DNS 的优先顺序，取决于 resolver（名称解析器）配置和应用实现，不能一概断言 hosts 永远优先于 DNS。

hosts 映射的是名称与地址，不指定端口，也不会建立代理连接、转发流量、改变网络出口或加密通信。若某名称解析结果有误，而目标 IP 本身可达，映射到正确 IP 可能解决名称解析问题；若连接本身不可达，仅改映射并不能修复连接。

## 反向代理：代表服务端接收请求

反向代理是代理的一类。客户端连接代理入口，代理再将请求转给后端服务。它可以部署在本机、内网或其他位置；是否位于本机、境内或境外，不改变“反向代理”这一角色定义。

以下是请求路径示意，不是 Nginx 配置：

```text
浏览器 → localhost:80（反向代理）→ localhost:8080（后端服务）
```

## 正向代理：代表客户端访问服务

正向代理接受客户端的请求，并代客户端访问目标服务。代理是一种网络中介技术；它本身不等同于绕过封锁，也不能仅凭“使用代理”推断其用途或可达性。

## 判断要点

- 只修改名称到 IP 的静态映射：属于 hosts 配置。
- 客户端访问服务端入口，由入口转发到后端：属于反向代理。
- 客户端通过代理请求目标服务：属于正向代理。
- 代理不会因为名称或部署位置自动获得特定的网络效果；需要根据实际代理协议、路由和网络条件判断。
