# 模块安装验证与脚本执行安全

## 安装提示成功不等于安装完成

一则历史兼容报告称，Magisk 27006 代号版本及当时的 KSU 最新版移除了旧版安装脚本支持。作者观察到，部分尚未适配的模块刷入后可能显示成功，但模块实际上没有安装。报告将原因描述为安装脚本使用的变量被移除，但没有给出变量名；“当时 KSU 最新版”也没有具体版本号，因此不能据此判断当前版本行为。

验证模块时应把安装器提示与实际结果分开记录：

- 保存安装日志，确认脚本是否正常执行及模块是否被系统识别。
- 按模块文档核对其预期状态或功能是否实际出现。
- 如果只有“刷入成功”提示而没有后续验证，应标注为“安装结果未确认”，不要报告为已安装。
- 兼容性结论需写明管理器及其具体版本、模块版本和测试结果。

作者当时提到爱玩机工具箱提供“关闭传统模式”作为兼容绕法，并提到替换模块脚本或使用模块工坊第七期修复。原帖四张配图未读取，且没有足够信息说明具体操作、脚本内容或菜单路径；这些历史提及不能作为可直接照做的步骤，也不保证对当前版本有效。

## 避免误执行不可信脚本

另一则作者自述的事故记录称，调试过程中投屏鼠标发生偏移，误点执行了脚本，设备随后进入 9008。作者称之后借助他人协助恢复，并重新修复了 tree、指纹等传感器相关功能。帖子没有提供可验证的命令、设备型号、完整恢复流程或适用于其他设备的步骤。

可推广的操作防护仅限于：执行前核对当前选中的脚本和目标；不要运行来源不可信、用途不清楚的脚本；投屏或远程控制有延迟、偏移时先停止点击并确认画面状态。发生故障时，本案例不足以构成救援教程，应寻求与具体设备和故障状态匹配的可靠支持。

不要复制或执行未经核实的恶意脚本。本文不提供进入 9008、分区操作或传感器修复命令。
