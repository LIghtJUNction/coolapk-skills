## 框架与兼容性声明

作者称 ROM 基于 MimosaFramework，采用 Android X 动态注入及 HOOK 注入，支持免 Root 运行，并称系统应用更新后功能不易失效。原文对 MitsuhaFramework 的上游描述存在缺字，不能补写缺失名称。这些均是作者对框架和功能的声明，没有独立实现审查或验证结果。

“免 Root 运行”不等于所有功能均免 Root，也不意味着帖子给出的缓存清理步骤免 Root。原帖明确写到 MT 管理器需授予 Root 权限；TWRP 文件管理是否可用取决于设备与 Recovery 状态，原帖没有给出兼容条件。评论中关于 Root 后功能生效或不生效的反馈，按机型分别收录。

作者称更新系统应用后修改“不易失效”；有用户在个别帖子评论提醒系统应用更新可能使 Hook 无效。两种说法不能合并成保证，帖子没有列出按应用或功能区分的结论。

## 版本、升级与刷机边界

原帖存在需要并列保留的刷入说法，不能据此承诺兼容：

1. 正文开头称支持从“本人任何 OS4 ROM 或相近官方包”直升；仍在 OS3 时建议先走官方渠道升级 OS4，再刷入以降低变砖风险。
2. 注意事项又称解锁 BL 后任意版本可直接刷，不需要任何底包；同时称无官方底包时问题较多，并提示仅供尝鲜。
3. 作者建议从其他作者的包切换时清空数据；又称官方包不清数据刷入（包括升级系统）可能遇到系统应用闪退或“假掉基带”，并强烈建议清数据。

以上是原帖相互并存的条件和风险提示。帖子未提供各机型、各来源 ROM、具体底包与刷法的兼容矩阵。刷机要求解锁 BL；作者表示刷入即承担刷机风险。清数据可能导致资料丢失。

作者还称刷机后可能长时间停留在第二屏，首次启动卡顿、发热与系统加载和自动编译有关，建议接充电器一晚或静置20–30分钟。这是作者说明，不是启动时间或性能保证。

### FRP 相关原帖建议

作者写到刷机前退出 Google 账号，或清除 FRP 分区。这里仅记录原帖建议：现有材料没有证实清除 FRP 的机制、必要性，也没有证实账号锁与评论事故之间的因果关系。不能把该建议解释成清除账号锁的可靠方法。

### 缓存目录与访问条件

原帖提供两种可选方法，二选一：用 MT 管理器并授予 Root 权限，或用 TWRP 文件管理器访问；删除所列目录后重启：

```text
/data/system/package_cache/
/data/dalvik-cache/
```

这是作者提供的可选建议，不是所有设备必须执行的步骤，也不能扩展为删除其他目录。MT 方法明确需要 Root；TWRP 能否访问这些目录、以及适用的 Recovery 条件，原帖没有说明。这里不提供额外清理命令。

### AVB 声明

作者称包内置系统内 AVB 校验，密钥与打包前不一致可能导致无法进入系统，并禁止二次修改、打包。这是作者的描述，不构成安全审计、安全保证或可验证的信任声明。
