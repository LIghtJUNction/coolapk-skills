## 签名能说明什么

数字签名用于让验证方检查签名是否与特定内容及签名密钥相对应；信任链则用于建立证书与签发者之间的信任关系。具体算法的验签过程可能不同，不应把“公钥解密签名”当成所有签名方案的通用原理。

有效签名能提供内容完整性检查，并在信任关系成立时说明相应密钥对内容作了签名。它本身不证明模块没有恶意行为，也不能阻止有人物理修改文件；修改后通常会导致原签名验证失败。帖子对 BL 锁、内核和 TEE 的概括不是不可更改保证，不能作为设备安全性的普遍结论。

## Kam 中的签名与验证

帖子所述 Kam 操作：

```sh
kam secret import main <私钥文件路径>
kam secret list
kam secret get main
kam sign <目标文件>
kam verify <目标文件>
kam verify <目标文件> -v
```

导入私钥时会要求设置密码；`kam secret get main` 会要求输入密码。帖子称 `kam sign` 会生成 `.sig` 后缀的签名文件；若签名文件与目标文件同目录，`kam verify` 无需另行指定路径。验证他人的签名需要取得对应公钥。

自动化工作流导入私钥的帖子示例使用 GitHub Actions secret 名称 `KAM_PRIVATE_KEY` 保存私钥文件内容。私钥本身及账户令牌不应放入公开文档或公开仓库。

帖子还称 Kam 当时没有对密文读取设计暴力破解速率限制，并认为私钥保护依赖密码复杂度。这属于原帖对实现的描述，不构成对当前实现的审计结论。

## ZIP 与签名文件选择

一则帖子观察到，模块管理器界面同时给 ZIP 包与同名 `.sig` 签名文件显示安装按钮，列表顺序也会变化；选择签名文件后安装失败。`.sig` 是供验签的旁侧文件，不是模块 ZIP 安装包。使用界面时应确认选择实际模块压缩包，而不是签名文件。
