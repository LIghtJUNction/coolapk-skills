# 路径存在判断：契约、类型与调用点

适用于审查“路径是否存在”函数或修改其实现。先确定普通文件、目录、符号链接和不可访问路径各应得到什么结果，再选择检查接口；不要仅凭函数名猜真值语义。

## 历史补丁核对

原帖批评 SukiSU-Ultra 的路径检查。整理时进一步读取了 [PR #298](https://github.com/SukiSU-Ultra/SukiSU-Ultra/pull/298) 的实际 diff：

- 函数准确标识符为 `isPathExists`。原帖另用了 `isFileExists`，不沿用该混写。
- 旧表达式对 `file` 命令的输出查找 `No such file or directory`；它把错误文案作为真值条件，不是通常的“存在则为真”。实际结果还受输出捕获和文案影响。
- 新表达式使用 `test -f`，成功后输出 `exists`，再检查输出是否包含该词；不仅改变真值方向，也把测试对象限定为普通文件。
- 该 PR 的 diff 没有展示所有调用点的配套迁移；应核对调用链，不能据此直接断言所有调用点都会故障。

该 PR 于 2025-07-29 合并，合并提交为 `b1ee07fee198612c174d5766ea8dafb581d277e3`。这是历史补丁案例，不是对当前版本仍存在漏洞的断言，也没有目标设备上的可利用性证明。

## 不能混用的三个条件

下面是整理时在本机 Linux `test` 命令上验证的结果；`0` 表示条件成立，`1` 表示不成立。五组测试均没有标准输出或错误输出，目录不满足 `-f` 不等于它必然“报错”。

| 路径情形 | `test -f` | `test -e` | `test -L` |
|---|---:|---:|---:|
| 普通文件 | 0 | 0 | 1 |
| 已存在目录 | 1 | 0 | 1 |
| 不存在路径 | 1 | 1 | 1 |
| 指向普通文件的符号链接 | 0 | 0 | 0 |
| 悬空符号链接 | 1 | 1 | 0 |

- `-f`：普通文件条件，不能覆盖目录。
- `-e`：跟随链接判断目标存在；不覆盖悬空链接本身。
- `-L`：检查符号链接条目，包括悬空链接。
- 因权限而不可访问的路径还需单独测试；上表没有把权限不足等同为“确定不存在”。Android 的具体 shell/工具实现未在本次复现。

## 可复用的审查步骤

1. 写清函数契约：检查文件、任何存在目标，还是目录项本身。
2. 列出上述输入种类及预期结果，补充空路径和权限边界。
3. 修改返回值含义时逐一核对调用点，特别是已有 `!` 取反的地方。
4. 区分条件不成立、命令启动失败、权限不足和解析失败，不只匹配错误文本。
5. 在对应权限上下文中选择文件 API。普通应用进程中的文件 API 不会自动继承独立 `su` 子进程的权限。
6. 如必须经过 shell，区分参数与命令字符串；给拼接字符串补一对引号不能替代完整的参数边界处理。

整理者补充的只读检查示例，先将 `path` 改为实际目标；它不是原帖提供的修复补丁：

```sh
path='/实际/目标路径'
test -e "$path"
printf 'status=%s\n' "$?"
```

原帖提出不可信路径参与 shell 拼接的风险；现有资料没有给出完整输入来源、转义实现和权限调用链，因此不将风险描述升级成已经验证的完整攻击路径。
