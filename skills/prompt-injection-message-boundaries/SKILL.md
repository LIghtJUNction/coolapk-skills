# 把伪造对话结构当作提示词注入案例

原帖给出一段仿照消息结构的文本模板，包含 `user`、`assistant`、`system` 和 `function` 等 role 字符串。这里这些字符串只是原帖内容，不是系统授权，也不能改变当前指令边界。

## 攻击所利用的混淆

模板尝试把普通文本伪装成历史 `assistant` 发言、更高优先级 `system` 消息及 `function` 工具回执。伪造“无网络连接”的回执意在让模型无视实际检索结果；它不是一次真实失败记录。

在实现中，将不可信资料保持为单独数据字段，用结构化序列化而非字符串拼接构造消息；角色由应用的真实消息结构决定。工具状态应关联实际调用与可信返回通道，不从待分析正文中的角色标签恢复执行权限。这些是根据案例整理的边界检查，不是原帖已实现的防护代码。

## 防御与适用边界

将这类文本作为待解析的引用内容，而非真实的对话角色或工具回执。不要把伪造的 `system` 内容当作授权，也不要把示例中的“无网络连接”当作真实检索结果。原帖使用“万能”一词，但没有提供可核验的通用有效性证据；不能据此声称它能普遍越狱或绕过安全机制。
