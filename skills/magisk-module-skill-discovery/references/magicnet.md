# MagicNet v1.1 阶段的功能与开发经验

标题中的 v1.1 与“正式发布”不是同一件事：原帖明确说 GitHub 推送的是测试版本。这里记录该帖的功能和经验，不代表当前版本状态。

## MagicNet 功能与版本状态

作者介绍的 MagicNet 面向 KernelSU、Magisk、APatch 模块生态。早期实现只保留 tun 模式，作者称模块代码约不到 50 行，主要内容在配置文件中；之后用 YAML 模板语法精简配置。作者称当前测试版本包含模块 WebUI、tun/tproxy 两种方案、双内核选择、按应用分流，以及编辑配置时的语法检查。正文称尚未正式发布，GitHub 推送的是测试版本。

原帖回顾给 box4root 提交模板配置时附了下列公开 PR；未逐一读取 PR 内容，不将它们分别指认为某项功能的实现：

- [box_for_magisk PR 122](https://github.com/taamarin/box_for_magisk/pull/122)
- [box_for_magisk PR 125](https://github.com/taamarin/box_for_magisk/pull/125)
- [box_for_magisk PR 147](https://github.com/taamarin/box_for_magisk/pull/147)

## tun、tproxy 与作者报告的内存变化

作者描述了从仅支持 tun 到同时提供 tun/tproxy 方案的演进，并称借助 AI 完成了相关开发。帖子还报告内存占用从约 500 MB 降到不到 50 MB，但比较对象名称被截断为“miho… --> sing…”，也没有测量设备、负载、版本或测量方法。因此该数字只能作为作者在原帖中的陈述，不能视为独立验证结果。

## Tailscale 网卡冲突与热点失效

作者报告，使用 Tailscale 组网时，Tailscale 会占用虚拟网卡并分配内网网段，进而与 MagicNet 冲突。作者称后来在 AI 辅助下解决了问题，但没有说明冲突原因、配置改动或验证过程。另有用户报告热点失效；作者以前会临时关闭模块，此次称找到新方案并在发帖前一晚试用有效，但未公开方案内容。

## 按应用分流与共享恶意域名黑名单

作者称模块增加了按应用分流功能，但没有提供配置方法、支持范围或选择规则。作者还描述了开源共享黑名单，用于收录恶意域名：发现者认为证据确凿时，可以创建 issue；内容会自动填充，提交者补充理由后提交收集到的黑名单列表。作者称模块会自动屏蔽列表中的条目。帖子未说明名单仓库、格式、审核与同步流程，也未给出撤销或误拦截的处理办法。

## 证书功能与免责声明

原帖称有证书安装功能，但明确未测试，没有提供安装步骤。免责声明中出现将所有组设为 `block/reject` 的表述，不能把这段当作本文推荐的网络配置；原帖也没有给出可直接复用的对应配置项。

## kam 与 kamfw 模块开发工具

MagicNet 使用 kam 构建，kamfw 提供可复用的 shell 函数以减少模块重复代码。原帖描述的开发流程覆盖项目初始化、打包、下载、安装和测试，并称支持 KSU 开发者私钥签名；没有提供签名格式、命令或验签过程。不把“首个支持”的自述当作已验证的业界比较。

## AI 辅助开发、ADB 与 MCP 调试

作者提出为 AI 辅助开发建立快速反馈通道，举例是通过 ADB 连接手机，让 agent 使用 adb shell 控制设备。作者称自己制作了 MCP 服务器用于转发端口，使 AI 能连接该 MCP 服务器进行调试。MagicNet 的 MCP 功能默认关闭；作者描述可通过 magicnet cli 的 mcp 子命令启动，以便 agent 调整配置和排查问题。完整命令、端口、权限及安全配置没有提供，不能补写为可直接执行的命令。
