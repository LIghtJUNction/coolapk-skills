# P2WLAN：虚拟网卡、直连与中继机制

## 虚拟网络接口
原帖将 P2WLAN 描述为 MIT 许可的组网工具，为设备分配私有虚拟 IP，使不同网络后的设备像处于同一局域网。各平台使用系统虚拟网卡：macOS 的 utun、Windows 的 Wintun、Linux 的 TUN。应用可以通过虚拟 IP 使用 ping、SSH、RDP、数据库连接或浏览器后台；原帖称无需开放公网端口。

## 连接路径
原帖描述三段式路径，客户端可查看当前路径：
1. LAN Direct：同一局域网直接连接。
2. 公网 UDP 打洞：跨网络尝试 IPv6/IPv4 点对点连接。
3. 加密 Relay：前两种路径不通时回退到中继，应用仍使用同一个虚拟 IP。

其 Rooms（房间）机制用于把游戏、协作、维护等设备关系分组隔离。原帖称 UDP 打洞通过两端同时向对方推测的出口地址发包，让 NAT 建立映射；复杂 NAT、CGNAT、企业防火墙或云安全组可能导致直连失败，此时回退 Relay，代价是延迟增加。

## 限制与安全边界
- 原帖称项目仍处 Preview，README 声明尚无独立安全审计；不宜据此将其视作已审计产品。
- 原帖称其加密数据面是 WireGuard-like 自研实现，不宣称与 WireGuard 互操作，不能直接接管现有 WireGuard 配置。
- Relay 转发密文，但原帖称仍可见节点标识、连接时间和包大小等元数据。
- 自托管需自行承担服务器、带宽、域名和运维成本。
- 原帖称 Android 客户端可用，iOS 为实验性预览；工具连接的是自己的设备，不提供访问公网的能力。
- 原帖将其与 Tailscale 作概括性比较，称 P2WLAN 面向希望掌控数据路径的使用者；输入未提供对照测试或项目文档链接。
