# 用共享文件协作推进长时任务

## 适用场景
适用于任务可能持续数小时、需求会迭代，且用户与本地 coding agent 都能访问同一云盘文件的情形。

## 工作流程
1. 在共享云盘中创建需求文件，写明目标、需求和验收条件。
2. 让本地 agent 依据该文件推进任务。需要长期运行时，可使用其支持的目标或任务机制；帖子以 `/goal` 为例，但未定义具体工具行为。
3. 需求变化时，编辑云端文件。更新可以由用户手动完成，也可以通过聊天产品连接的插件完成。
4. agent 若支持检查文件编辑记录或只读取变化部分，可据此获取更新；这是帖子描述的工作方式，不保证其他 agent 具有相同能力。
5. 用户和 agent 通过共享文件交换目标与更新。用户可以离开本地电脑，但任务能否继续取决于本地 agent 进程及其运行环境是否仍在工作。

## 边界与核查
- 云端目标文件被更新，表示协作目标已更新；这本身不表示本地 agent 已读取更新。
- 本地 agent 读取或检查文件，需要其实际运行并能访问云盘；帖子没有证明离线时会有后台自动执行。
- 不假设任务会持续运行、自动恢复或必定不会提前结束。应检查 agent 当前状态及其对文件变更的读取方式。
