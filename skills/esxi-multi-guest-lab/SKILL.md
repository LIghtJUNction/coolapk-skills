# ESXi 多系统实验机与远程管理案例

原帖前提是已有 N5105 小主机和 ESXi 7.0，不包含 ESXi 安装。三台虚拟机分别承担软路由、桌面和 Linux 服务；没有给出整机总内存、持续负载或性能隔离测试，不能把“一机多用”理解成任意资源配置都能稳定运行。

## 系统资源

| 系统 | 原帖设置或用途 | 已核对的公开入口 |
|---|---|---|
| iKuai | Linux 64 位客户机；示例 2 vCPU、1G 内存、20G 磁盘；ISO 光驱安装，取消安全引导 | [iKuai 固件下载](https://www.ikuai8.com/component/download) |
| Windows 10 | 64 位客户机、ISO 安装，示例选专业版；未给出 CPU/内存数值 | 原帖未提供可恢复的官方镜像地址，不用不明镜像冒充官方文件 |
| Ubuntu 22.04 Server | 用于服务与 cpolar；原帖未完整给出资源数值 | [Ubuntu 22.04 官方镜像目录](https://releases.ubuntu.com/22.04/) |

**原帖的 1G 不是当前 iKuai x64 的推荐值。** 2026-11-14 查到的 [iKuai 下载页](https://www.ikuai8.com/component/download) 将 64 位内存条件列为至少 4GB。旧案例参数与当前要求分开记录，具体版本还需匹配。

原帖提到镜像合集和公开提取码 `1314`，但正文没有可恢复的分享 URL；因此这里不把它宣称为可下载的镜像资源。

## 虚拟机安装顺序

1. ESXi 中创建虚拟机，选择客户机类型、存储与资源，把对应 ISO 挂到虚拟光驱。
2. iKuai 示例启动后按安装提示依次确认，进入系统后用菜单修改 LAN 地址，使管理端可达。原帖使用初始 `admin/admin` 登录；这不是已配置好的私人账号，也不应保留为正式管理凭据。
3. Windows 示例选择自定义安装，安装到虚拟磁盘；原帖称配置网口后可访问 iKuai，但未提供具体虚拟交换机和网卡映射。
4. Ubuntu 示例完成安装和用户设置，启用 SSH 后重启登录。原帖许多安装器选项只在未读图片里，不能据正文补造完整点击顺序。

原帖没有列出 vSwitch、Port Group、WAN/LAN 端口、VLAN 或物理网卡直通关系。建好三台虚拟机并不等于软路由隔离和转发已经配置完成。

## cpolar 安装：原帖与补充官方方法分开

原帖对部分地址插入“删”字，并明确让读者移除。它的旧安装命令恢复为 `sudo curl https://get.cpolar.sh | sh`；其中 `sudo` 只作用在下载端，不能据此说整条管道都以 root 执行。本次未执行或验证旧脚本。

整理时核对的 [cpolar 官方 Linux 文档](https://www.cpolar.com/docs) 给出另一条安装命令；下列是官方补充，不伪称为酷安原帖命令：

```sh
curl -L https://www.cpolar.com/static/downloads/install-release-cpolar.sh | sudo bash
cpolar version
sudo systemctl status cpolar
```

文档还给出账号认证步骤。认证令牌必须取自使用者自己的账号，不放入公开技能。这里未运行安装脚本或创建任何隧道。

## 原帖隧道配置过程

1. 在浏览器访问 Ubuntu 虚拟机地址的 `9200` 端口并登录 cpolar 管理界面。此端口是 cpolar 管理界面，不是 ESXi 地址。
2. 在隧道列表编辑示例 website 隧道，改名为 `esxi`，把本地目标指向实际 ESXi 管理地址。
3. 原帖选择 `China Top` 地区，更新后在在线隧道列表查看分配的地址，以 HTTPS 地址测试访问。
4. 固定二级子域名时，原帖先在账号后台预留地区和名称，再回到隧道编辑页选择对应域名类型。名称只是用户自定标识，不存在所有账号通用的固定名称。

这是把宿主管理面转为公网可达的案例。原帖没有给出来源访问限制或额外认证的配置，不能据此当作可直接投用的公网管理方案；外侧 HTTPS 也不能单独证明目标侧连接与访问控制均已妥当配置。

原帖声称免费随机域名约每 24 小时变化、升级套餐可固定域名。这些是原帖的服务条件描述，本文未核对当前套餐，不据此承诺今天的价格、权益或地址生命周期。
