# Piik：基于 WebRTC 的临时屏幕共享

## 基本使用
原帖介绍的流程：打开 Piik 创建房间，选择整个屏幕、单个窗口或浏览器标签页，然后分享邀请链接。观众用手机或电脑浏览器打开链接，无需安装应用。房主不占观众名额；默认最多 20 位观众，服务端可配置为 1–20 人。

功能包括房间密码、画中画、深色模式和播放控制。原帖称暂停状态可保持，断线重连不会重置播放进度。分享时优先选单个窗口，可减少无关画面传输，也降低意外暴露其他窗口内容的风险。

## 连接架构与限制
Piik 优先通过 WebRTC 建立 P2P 直连。P2P 仍需信令服务器在连接建立前交换握手信息；原帖描述为连接建立后画面直接在设备间传输，不经过中心服务器中转。

WebRTC 直连依赖 NAT 穿透。对称 NAT、企业防火墙或部分校园网可能导致连接失败。自托管时可启用服务器转发 SFU 作为回退；原帖称公开演示站仅提供 P2P，没有 SFU 兜底。自托管的具体命令和配置未在正文给出。

原帖给出的边界：20 人上限适合朋友、小团队和临时围观，不适合较大部门会议。macOS 与 Linux 的物理屏幕采集尚需设备测试；Windows 被称为现阶段较稳，但没有给出测试机型或测试数据。项目版本迭代较快，文章记录一周内从 v1.3 到 v1.5.3，重大场合应先验证所用版本。

Piik 用于屏幕共享，不提供远程控制对方电脑的功能。邀请链接应按访问凭证保管；共享前关闭聊天、密码管理器和邮箱等敏感窗口。
