# 旧版 Android 游戏的 APK 路径缓冲区问题

帖子记录了一次让旧游戏适配较新 Android 系统的排错案例：运行日志出现 `Error Loading APK`。发帖者报告称，通过 IDA Pro 定位到代码中的 `char gApkPath[64]`，用于保存 APK 路径的缓冲区长度不足。

案例中的路径为：

```text
/data/app/~~<随机目录>/gts.defence.lite.en.cmcc-<随机后缀>/base.apk
```

上方使用占位符表达路径结构，不公开实例中的随机安装目录；它不是用于复算长度的字面路径。

协调者按私有原始实例逐字节复算：该纯 ASCII 路径为 **95 字节**；以 NUL 结尾存储完整 C 字符串需要 **96 字节**。`char gApkPath[64]` 最多容纳63个内容字节加结尾NUL，因此不足。本例 ASCII 字符数等于字节数；其他编码的数据不能直接按显示字数估算容量。

固定容量不足可导致截断、拒绝或越界，具体取决于实际拷贝代码。原帖没有给出完整拷贝代码，不能据此确认发生了缓冲区溢出，也没有补丁或复测证明游戏已修好。

整理建议：从运行环境取得实际路径，按所用字节序列计算所需空间；使用动态存储，或在复制前检查内容长度加NUL是否超过容量并明确处理失败。把64简单改成另一个固定值，不能证明所有后续安装路径都能容纳。以上是由容量约束得到的建议，不是原帖已经实施的修复。
