# 用文本表示游戏世界，供 Agent 观察和规划

围绕《缺氧》（Oxygen Not Included，ONI）和 OniMcp 的两条动态描述了一个游戏控制接口的演进：游戏通过 Mod 暴露操作，启动时由 Mod 创建 MCP 服务器；之后将游戏平面转换成虚拟文本文件，让 AI 读取和编辑，再由 Mod 把编辑结果转换回游戏操作。

## 控制方式的演进

1. **直接传入坐标。** 早期方案让 AI 提交坐标来建造房间；作者称这种方式速度慢，且容易放置偏差。
2. **独立游戏鼠标。** 后续方案为 AI 提供一个独立于玩家鼠标的游戏鼠标。作者称效果有所改善，但仍不够快、效果也不理想。
3. **文本化世界状态。** 将游戏平面转换为虚拟文件，供 AI 读取和编辑；Mod 再将编辑结果翻译为游戏操作。作者称这种表示也解决了此前未解决的连线问题，并举出自动化门锁设计作为例子。

这描述的是接口机制和作者对效果的观察。随帖图片未在本次资料中核验，因此不能据此验证画面或量化速度、准确率和效果提升。

## 连接方式

另一条动态称游戏启动时 Mod 会自动运行，并在一个端口创建 MCP 服务器；使用 HTTP Streamable。作者明确表示不推荐 SSE 和 stdio。安卓模块开机自启动也被作为类似思路提及，作者指出这种情形必须加入认证，否则风险很高。原文没有提供端口号、认证配置或具体部署步骤，不能补造。
